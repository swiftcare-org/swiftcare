# Mutation Testing (SWC-151)

Owner: Kularatne P.O.N (IT24103437). SE3112 role: Mutation Testing.

Line coverage shows which code the unit tests execute, not whether they would notice a bug.
Mutation testing measures that directly. [Stryker.NET](https://stryker-mutator.io/docs/stryker-net/introduction/)
makes small deliberate changes (mutants) to the service code, such as `<` to `<=`, `&&` to
`||`, `true` to `false` or removing a statement, and runs the existing unit tests against
each one. A mutant is **killed** when at least one test fails, and **survives** when every
test still passes. Each surviving mutant points to a behaviour the tests do not check.

## Scope

| Service | Unit-test project | Config |
|---|---|---|
| ApiGateway | `tests/ApiGateway.UnitTests` | `configs/stryker-apigateway.json` |
| AuthService | `tests/AuthService.UnitTests` | `configs/stryker-authservice.json` |
| MedicalRecordService | `tests/MedicalRecordService.UnitTests` | `configs/stryker-medicalrecordservice.json` |
| NotificationService | `tests/NotificationService.UnitTests` | `configs/stryker-notificationservice.json` |
| PatientService | `tests/PatientService.UnitTests` | `configs/stryker-patientservice.json` |
| PrescriptionService | `tests/PrescriptionService.UnitTests` | `configs/stryker-prescriptionservice.json` |
| QueueService | `tests/QueueService.UnitTests` | `configs/stryker-queueservice.json` |

NotificationService was added after the other six, once its code and unit tests were merged.

Every hand-written source file is mutated: controllers, services, middleware, models,
validation, logging helpers, maintenance commands and Kafka publishers and consumers.
Excluded, with the reason:

| Excluded | Why |
|---|---|
| `Migrations/` | Generated by EF Core. Checked by the CI `validate-migrations` job. |
| `Data/` | DbContexts and MySQL repositories. They need a real database, so they belong to integration and E2E tests, not unit tests. |
| `Program.cs` | Composition root. A mutant there breaks startup for every test at once, which says nothing about the tests. |
| Logging calls (`ignore-methods`) | Mutating log messages produces survivors that do not change behaviour. |

Settings shared by all seven configs:

| Setting | Value | Why |
|---|---|---|
| `mutation-level` | `Standard` | The full set of C# mutators without the slowest experimental ones. |
| `coverage-analysis` | `perTest` | Each mutant runs only the tests that reach it, which keeps a full run practical. Mutants no test reaches are reported as **NoCoverage** without running anything. |
| `thresholds` | break 80-90, low = break, high = break + 5 | `break` is set per service 5 points below its final score, so CI fails if the suite is weakened (see Results). Stryker requires high ≥ low ≥ break. |

## Prerequisites

- .NET 10 SDK
- Windows PowerShell 5.1 or PowerShell 7
- Stryker.NET 5.0.0 comes from the repository tool manifest; the script runs `dotnet tool restore`.

No database, Kafka or Docker is needed. Only unit tests run.

## Run

From `tests/MutationTesting/`:

```powershell
# All seven services
./run-mutation-tests.ps1

# One or more services (quote a comma-separated list when using powershell -File)
./run-mutation-tests.ps1 -Service "PrescriptionService,QueueService" -OpenReport

# One file, about a minute (live demo)
./run-mutation-tests.ps1 -Service PrescriptionService -Mutate "**/Services/PrescriptionManagementService.cs" -OpenReport

# Only code changed since develop (pull request mode)
./run-mutation-tests.ps1 -Since develop
```

If script execution is blocked on Windows, run it as
`powershell -ExecutionPolicy Bypass -File ./run-mutation-tests.ps1`.

## Output

All output goes to `results/` (git-ignored, except the `RESULT-*.md` reports):

| File | Content |
|---|---|
| `results/summary.md` | Combined table: mutants, killed, survived, no coverage, mutation score and covered score for each service, plus undetected mutants grouped by mutator. Also written to the GitHub Actions job summary. |
| `results/<Service>/reports/mutation-report.html` | Stryker's interactive report. Open a file to see each mutant inline with its status. |
| `results/<Service>/reports/mutation-report.json` | Machine-readable report (mutation-testing-elements schema). |
| `results/<Service>/survivors.md` | Every surviving and uncovered mutant with file, line, mutator and replacement. |

The script exits with code 1 when any service scores below its break threshold.

### Reading the results

| Status | Meaning |
|---|---|
| Killed | A test failed. The tests detect this change. |
| Timeout | The mutant caused an infinite loop or hang. Counted as detected. |
| Survived | Every covering test passed. A test gap, or an equivalent mutant. |
| NoCoverage | No test executes this code. |
| CompileError | The mutant does not compile (a stillborn mutant). Not counted. |
| Ignored | Excluded by configuration. Not counted. |

- **Mutation score** = (killed + timeout) / (killed + timeout + survived + no coverage)
- **Covered score** = (killed + timeout) / (killed + timeout + survived). This rates only the code the tests reach.

An **equivalent mutant** changes the code without changing behaviour (for example `>=` to `>`
where the two values can never be equal), so no test can kill it. These are recorded with a
justification in the result report instead of being "fixed".

## CI

The `mutation-testing` job in `.github/workflows/ci.yml` runs after the .NET build and test job.
One matrix leg runs `run-mutation-tests.ps1` for each of the seven services above, and each
leg reports as its own check, `Mutation testing (<Service>)`.

| Event | Runs | Mutates |
|---|---|---|
| Pull request into `develop` or `main`, opened or updated | Yes | Code changed since the base branch (`-Since origin/<base branch>`) |
| Manual **Run workflow** | Yes | Every service in full, on the chosen ref |
| Push to `develop` or `main` (a merge) | No | - |
| CD calling CI (`workflow_call`) | No | - |

Why it runs where it does:

- **Pull requests** are where a weaker test suite can still be stopped. A leg fails when its
  service scores below its break threshold, and the seven checks are required in the `develop`
  and `main` branch rulesets, so that blocks the merge. Mutating only changed code keeps a pull
  request run to minutes.
- **Not on push or in CD.** The merged code already passed on its pull request, a failure after
  the merge could no longer block it, and a full run (about 25 minutes) would delay every
  deployment.
- **A full run** of every service is started manually with **Run workflow**, for example before
  a release or to refresh the results below.

Each leg writes its score table to the GitHub Actions job summary and uploads its result
directory as `mutation-report-<Service>`, including the HTML report. Upload runs even when the
mutation step fails. The script fails when the service scores below its break threshold or
produces no report.
